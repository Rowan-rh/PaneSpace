## Why

整体代码审查发现五个用户很容易碰到的高优先级问题：分栏视图会被无关的文件系统变化折叠；应用包被当作普通文件夹进入；Tab 切换活动面板后键盘焦点仍停在旧面板，可能对错误面板执行删除；搜索过滤后仍会对看不见的选中项执行操作；右键菜单在多选时各项作用范围不一致。前三项会破坏浏览上下文，后两项可能让用户误操作文件，需要优先修复。

## What Changes

- 分栏视图刷新（手动刷新、目录监听、传输完成）时原地重新加载所有列，保留列路径和各列选择；只有显式导航才重建列。目录监听覆盖分栏视图中所有显示的目录。
- 文件列表区分应用包等包类型：包按文件对待，双击或打开会交给系统打开，方向键与分栏选择不会进入包内部；排序中不与文件夹同组置顶。
- 使用 Tab / Shift-Tab 切换活动面板时，键盘焦点同步移到新活动面板的文件内容区；鼠标点击路径栏、搜索框等控件时不抢夺焦点。
- 选中项相关的操作（删除、传输、Quick Look、在 Finder 中显示、状态栏计数）只作用于当前可见的选中项，并按显示顺序处理。
- 列表视图的右键菜单统一作用于“被右键的项；若它属于当前选择则为整个选择”；右键“移到废纸篓”与 Delete 键使用同一确认流程；双击和回车通过菜单的主操作打开所选项。

## Capabilities

### New Capabilities
- `column-view-refresh`: 分栏视图在刷新和目录变化时保留列路径与选择，并监听所有显示的列目录。
- `package-items`: 应用包等包类型在浏览、打开和排序中按文件处理。
- `pane-keyboard-focus`: 键盘切换活动面板时焦点跟随活动面板。
- `selection-scoped-actions`: 选中项操作只作用于可见选中项，右键菜单作用范围一致，并统一删除确认。

## Impact

- `BrowserPaneModel`：刷新流程拆分为“导航重建”和“原地刷新”，目录监听改为按显示目录集合管理，`selectedItems` 基于可见项并保持显示顺序，删除接口改为接收目标项。
- `FileItem` / `LocalFileProvider`：新增包标记，读取 `isPackageKey`。
- `AppModel`：新增键盘切换面板后的焦点请求。
- `BrowserPaneView`：列表右键菜单改为基于选择类型的菜单与主操作，删除确认统一，面板焦点请求响应。
- 为以上行为补充 `BrowserPaneModelTests`、`LocalFileProviderTests`、`AppSessionTests` 回归测试；无新依赖，不改变持久化格式。
