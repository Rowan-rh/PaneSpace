## Context

动机见 `proposal.md`。当前仓库的开发集成分支名为 `develop`，没有 `developers` 分支。`AGENTS.md` 定义工程约束和完成条件；`CONTRIBUTING.md` 只有简短步骤；`docs/DEVELOPMENT.md` 记录工具链、命令、UI 检查和发布步骤；CI 会运行带警告视为错误的测试、构建应用包并检查签名。PR 模板重复了一部分验证清单。OpenSpec 已使用 `spec-driven`，但贡献指南尚未规定什么时候必须走 OpenSpec、如何记录合并以及何时归档。

## Goals / Non-Goals

**Goals:**
- 为每份流程文档指定清晰职责，避免同一清单维护多个版本。
- 将用户指定的 `develop` → 功能分支 → 合回 `develop` → 推送 → 面向 `main` 的 PR 流程写清楚。
- 记录用户允许助手在需要时直接操作 `main`，同时保留可追踪的合并历史和中文变更说明。
- 让 OpenSpec 的使用范围与改动规模相称，并统一本地、CI 和 PR 的验证证据。

**Non-Goals:**
- 不更改 CI job、分支保护、发布签名或单人维护阶段的 GitHub 权限设置。
- 不要求对拼写、常规文档编辑或不改变可观察行为及架构的小修复编写行为规格。

## Decisions

### 区分每份文档的职责

- `AGENTS.md` 保持为简明的仓库级工程契约：架构、隐私、代码质量、完成条件，并链接到详细验证清单。
- `CONTRIBUTING.md` 说明贡献者完整流程、分支约定、OpenSpec 判断规则、合并路径和收尾归档。
- `docs/DEVELOPMENT.md` 负责开发环境、命令、UI 验证矩阵和发布步骤。
- `.github/pull_request_template.md` 收集中文变更摘要及对应验证证据，不另行定义检查标准。

让每份文档负责一种信息，比在多处复制整套步骤更不容易产生过期内容。

### 按改动类型使用 OpenSpec

新功能、用户可见行为变化、架构或 Provider 契约变化，需要先创建并评审 proposal、行为规格、必要的 design 和 tasks，再按任务实施。纯文档、拼写修复和不改变行为的小型问题可以走轻量流程；若仍记录为 OpenSpec 变更，则使用 `skip_specs: true`，不虚构产品行为规格。

实现时逐项更新任务；验证和相关文档更新完成后再归档变更。这样方案评审与实现完成状态都可以追踪。

### 默认从 develop 分支经 PR 进入 main

标准步骤为：从仓库当前的 `develop` 分支创建 `codex/` 或其他聚焦分支；开发并完成验证；用非快进合并将功能分支合回 `develop`，保留合并提交；推送 `develop`；创建以 `main` 为目标的合入请求，并以中文填写标题、摘要和验证结果。仓库目前没有名为 `developers` 的分支，因此文档和实际操作使用现有 `develop` 分支名。

项目负责人允许助手在需要时直接操作 `main`。如果采用直接操作路径，仍需保留清晰的提交或合并历史、避免强制推送，并用中文记录变更内容和验证结果。默认工作流仍优先创建目标为 `main` 的合入请求，确保主线变更有集中记录。

### 将 CI 与 macOS 界面检查视为互补验证

开发说明准确记录 CI 当前执行的自动检查：`swift test -Xswiftc -warnings-as-errors`、`make app` 和应用包严格签名验证。CI 不会启动桌面应用，因此改动可见界面时仍需在 macOS 上启动并检查；涉及共享面板内容时检查单面板和双面板，并按改动补充键盘、无障碍、本地化和最小窗口尺寸检查。

## Risks / Trade-offs

- **OpenSpec 步骤可能拖慢小修复** → 仅对功能、可观察行为和架构变化要求行为规格，明确轻量例外。
- **分支约定与仓库分支名不一致** → 以仓库现有的 `develop` 为准，并明确当前不存在 `developers` 分支。
- **直接改 main 会减弱 PR 集中记录** → 默认仍创建目标为 `main` 的 PR；直接操作时保留合并/提交历史并写中文说明。
- **流程继续散落在多份文档中** → 给每份文档指定信息所有者，以链接引用细节，避免复制完整清单。

## Migration Plan

同步更新四份开发文档，并对照 CI workflow、当前分支名和 main 规则集检查一致性。此过程不改应用代码或用户数据。新流程合入后，后续功能按该流程执行，并将已完成的 OpenSpec 变更归档，使 active 列表只保留进行中的工作。
