## Context

参见 `proposal.md`。面板的列表视图由 SwiftUI `List` 展示，选中项保存在 `BrowserPaneModel.selection`；模型已有异步目录加载、导航历史和 `goUp()`。路径栏和搜索栏是列表的相邻控件，文本输入必须继续接收自己的方向键。

## Goals / Non-Goals

**Goals:**
- 在列表获得焦点时将右/左箭头映射到进入选中目录和返回上级。
- 复用面板模型的导航和异步刷新，并在返回时恢复离开目录的文件夹选择。
- 在无效选择或根目录边界下保持安全的无操作行为。

**Non-Goals:**
- 不改变列视图的点击导航，也不在文本框编辑时截获方向键。
- 不改变双击打开文件、Command-↑、面包屑或导航历史按钮的现有操作。

## Decisions

- 将 `.onKeyPress` 处理器挂在 `FileListView` 的 `List` 上，而不是整个面板上。这样只有文件列表获得焦点时才处理按键，搜索词、路径编辑框仍使用系统默认光标移动。
- 列表视图切换目录时保留同一个 `List`，并在其上方显示加载、空目录或错误状态；这样加载完成后列表继续持有原键盘焦点，空目录也能继续接收左箭头。
- 右箭头只在模型找到一个被选中且当前可见的目录时调用目录导航；文件、多个选中项、不可见选中项和空选择都不改变路径。
- 左箭头沿用 `goUp()` 的上级目录导航并记录现有导航历史。导航加载前暂存离开目录的 URL；刷新完成后若该目录仍是上级列表中的项目，就按 URL 找到新 `FileItem.ID` 并恢复选择，避免依赖刷新前失效的 ID。找不到项目时清除暂存和选择。
- 根目录下不消费左箭头导航；处理器只将实际执行的导航按键标为 handled，避免改变其他按键行为。

## Risks / Trade-offs

- [SwiftUI `List` 已将方向键用于选择移动] → 仅处理左右键；上下键仍交由 `List`，并在实际 macOS 界面中验证焦点和选择行为。
- [返回期间目录被删除或不可访问] → 复用现有加载错误处理；父目录能读取时显示其内容，且不恢复失效选择。

## Migration Plan

无需数据迁移。若回归问题出现，可移除左右键处理器及返回选择暂存逻辑；现有点击、双击和 Command-↑ 导航保持不变。
