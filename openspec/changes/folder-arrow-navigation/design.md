## Context

列表视图由 SwiftUI `List` 展示，分栏视图由多列 `ColumnView` 展示。目录选择、当前路径和列内容由 `BrowserPaneModel` 管理。路径栏和搜索栏与文件内容相邻，文本输入必须继续接收系统默认的方向键行为。

## Goals / Non-Goals

**Goals:**
- 在列表和分栏视图中都能用右箭头进入选中的文件夹。
- 在列表视图中用左箭头返回上级并恢复离开目录的文件夹选择。
- 在分栏视图中用左箭头返回上一列，并让焦点与选择保持连贯。
- 复用模型已有的异步目录加载、导航历史和错误处理。
- 在无效选择、空目录和根目录边界下保持安全的无操作行为。

**Non-Goals:**
- 不改变双击打开文件、Command-↑、面包屑或导航历史按钮的现有操作。
- 不在路径栏、搜索框或其他文本输入中截获方向键。
- 不改变分栏视图的鼠标选择和文件拖放行为。

## Decisions

- 列表视图继续把左右键处理器挂在 `FileListView` 的 `List` 上。点击文件行时将焦点交给列表；进入和返回时保留同一个 `List` 实例，确保异步加载、空目录和错误状态下焦点仍可继续使用。
- 列表右箭头只在恰好选中一个可见目录时调用现有目录导航。左箭头沿用 `goUp()` 并暂存离开目录的 URL；刷新完成后按 URL 找回新 `FileItem.ID` 并恢复选择。文件、多选、空选择和列表根目录都不执行目录导航。
- 分栏视图由一个可聚焦的横向滚动区接收方向键，并单独记录当前活动列。鼠标选择行或左右键推进/返回时更新活动列；上下箭头在该列的可见排序结果中移动选择。这样避免 SwiftUI 在多个列焦点目标之间分派按键时把事件留给首列。
- 分栏浏览器在目录刷新期间继续留在视图层级中，临时隐藏内容并显示加载状态，以免异步导航销毁键盘焦点。加载期间方向键不操作过期列内容；加载完成后活动列切换到新目录。
- 分栏视图的右箭头要求当前列选中目录。若子列已经加载，则进入子列并选中第一项；若子列为空，则将焦点留在空列；若子列尚未加载，则等待加载完成后再选第一项。选中的是文件或没有唯一选中目录时不执行进入操作。
- 分栏视图的左箭头返回上一列，并重新选择打开当前列的父目录。若活动列是首列，则沿该列目录返回文件系统上级，并在加载后恢复离开的目录选择；文件系统根目录保持不变。
- 仅在文件内容的焦点范围内处理方向键，避免影响路径栏、搜索框和其他文本输入。

## Risks / Trade-offs

- [SwiftUI 控件会自行处理方向键和焦点] → 横向滚动区统一接收按键并按活动列分派；刷新时保留分栏浏览器实例，避免异步导航丢失焦点；在 macOS 单面板、双面板及两种视图中验证。
- [目录加载期间用户连续按键] → 先将焦点移至目标列，待列加载完成后再选中第一项；加载失败或目录为空时保留目标列焦点且不创建无效选择。
- [返回期间目录被删除或不可访问] → 复用现有加载错误处理；不恢复失效选择。

## Migration Plan

无需数据迁移。若回归问题出现，可移除列视图新增的焦点和方向键处理；列表视图现有行为、点击、双击和 Command-↑ 导航保持不变。
